# Key Management

## Key Types
| Key | Algorithm | Purpose |
|:---|:---|:---|
| DID signing key | Ed25519 | Sign DID-authenticated requests |
| Fabric enrollment key | ECDSA P-256 | Fabric transaction signing |
| Asset encryption key | AES-256 | Document encryption (wrapped) |

## Key Generation
- DID signing keys generated client-side in browser (Web Crypto API) or server-side in Identity Service
- Private key shown to user ONCE on DID creation; not stored by system
- Fabric enrollment keys generated by Fabric CA

## Key Storage (User)
- Private key responsibility is the user's
- System offers optional encrypted key escrow (Shamir's Secret Sharing recovery)
- Recovery requires N-of-M admin approval

## Key Storage (Service)
- Service account keys stored as Docker secrets / environment secrets
- Never in source code or version control

## Key Rotation
- Fabric CA certificates rotated per Fabric CA policy
- DID signing keys can be rotated by submitting new public key via `updateDID`

## Shamir's Secret Sharing (Advanced)
- Private key split into 5 shares; 3-of-5 required to reconstruct
- Shares distributed to 5 trusted admins
- Reconstruction requires 3 admins to present shares simultaneously
